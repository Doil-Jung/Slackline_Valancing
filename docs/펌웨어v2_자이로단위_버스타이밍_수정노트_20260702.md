# 펌웨어 v2 수정노트 — 자이로 단위·버스 타이밍·가속도계 보상 (2026-07-02)

신규 파일 (기존 v1 보존): `opencr_test/lqr_balance_current_v2/`, `opencr_test/compute_K_measured_v2.py`

## 발견한 코드 오류

1. **★자이로 단위 16.4배 (확정 — θ 폭주의 유력 직접 원인).**
   OpenCR IMU 라이브러리에서 `imu.gyroData[]`는 deg/s가 아니라 **raw LSB**
   (gRes = 2000/32768 ≈ 0.061 dps/LSB; 라이브러리가 `imu.gx/gy/gz`에 dps로 변환).
   모든 구 펌웨어(`lqr_balance`, `lqr_balance_current` v1, `fwe_demo_standalone` 등)가
   `imu.gyroData[1]*DEG2RAD`로 사용 → **θ̇ 16.4배 과대**.
   atan2·ratio는 스케일 무관이라 thAcc는 정상 → "기울기는 맞는데 움직이면 θ가 튐" 증상과 부합.
   v2: `imu.gy * DEG2RAD` 사용.
   검증: diag에서 1초에 90° 회전 → thDot ≈ 90 (버그면 ~1500).

2. **★57600 baud로 500Hz 불가 (확정).** pos·vel 읽기+전류쓰기 3 트랜잭션 ≈ 12~14ms
   → 실제 ~70Hz인데 Ad/Bd/K/L은 DT=0.002 가정. v2: 1Mbps 자동 승격(57600 발견 시
   BAUD_RATE=3 기록) + Present Velocity(128)~Position(135) 8바이트 **단일 read** +
   micros() 기준 정확 2ms 페이싱 + [RATE]<450Hz 경고.
   (구 lqr_balance.ino는 추가로 Ad가 DT=0.001로 계산돼 있었고 100Hz 시리얼 출력이 루프를 throttle.)

3. **엔코더·속도에 MOTOR_DIR 미적용 (잠재).** Dynamixel은 +전류=+위치(같은 회전방향)라
   MOTOR_DIR=-1로 뒤집으면 δ·δ̇ 부호도 함께 뒤집어야 함. v2: readDeltaBoth에 MOTOR_DIR 곱
   → CLAUDE.md §2.3의 "엔코더↔δ 부호 미해결"이 구조적으로 해소(브링업은 여전히 torque_cal로 확인).

4. **경미**: 마운트 오프셋·가속도 기준 단일샘플 → 200샘플 평균. commandTorque 반올림 부호 수정.
   `imu.begin(500)`으로 IMU 내부 갱신주기(기본 200Hz)를 제어주기에 맞춤.

## 센싱 개선 (v2 칼만)

측정모델 확장: 이 로봇은 정상 동작 중에도 발이 원호 위에서 흔들려 IMU에 상시 선형가속
→ v1의 1g 게이팅은 θ_acc를 자주 차단. v2는 소각 선형화에서
**z₀ = θ_acc ≈ θ − ẍ_imu/g**, ẍ_imu = [R, L1, ℓ_imu]·q̈ = 상태의 선형함수(M⁻¹(Gq+Dq̇+Eτ))
이므로 EKF 없이 **C행 확장 + τ 직결항(D0_FEED)** 으로 정확 반영. 게이팅은 모델 밖 충격
(베어링 스틱션 등) 안전장치로 유지, θ_acc innovation 클램프 0.5→0.15 rad.
신규 파라미터 **ELL_IMU(힙→IMU 거리, 예시 0.13m) ★실측 필요**.

검증(사이드 시뮬, 노이즈 포함 폐루프): 관측 rank 6, 관측기 max|eig|=0.9985,
θ 추정오차 최대 <1°(과도 중), 폭주 없음. 과도피크(1.1°→13°)는 CLAUDE.md §7.6의
알려진 LQR 느린 극 특성이며 추정기 문제 아님.
